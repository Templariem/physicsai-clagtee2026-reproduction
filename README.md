# Physics-AI — CLAGTEE 2026 reproducibility package

**A Physics-AI Framework for Video-Assisted Electric Potential Mapping Using 2D FEM: A Tesla Coil Case Study**

**Authors, in paper order:** Giovanni Cocca-Guardia, Gabriel Hermosilla, Hernán Mella, Gabriel Olmos, Manuel Silva, Lisa Soto, and Sebastian Quiñones. Pontificia Universidad Católica de Valparaíso, Chile. Corresponding author: Gabriel Hermosilla.

[Download the complete experiment assets](https://github.com/Templariem/physicsai-clagtee2026-reproduction/releases/tag/clagtee-2026-full-v2.0). The [standalone FEM solver](https://github.com/Templariem/maxwell_solver_fem_2d/releases/tag/clagtee-2026-v2.0) is also included under `fem/`.

This package contains the FEM implementation, meshes, reviewed frames/masks, grouped splits, calibrated targets, nine trained methods, predictions, figure generators and numerical records supporting the paper. It contains no camera application. No new training was performed to package this release.

## Reproduction levels

Install Python 3.14 and a CUDA-enabled PyTorch compatible with your NVIDIA GPU; install the remaining dependencies with `python -m pip install -r requirements.txt`. The exact tested environment is in `validation/environment_homelab.txt`. Gmsh needs the system OpenGL libraries (on Debian/Ubuntu: `libglu1-mesa`). The tested GPU is an NVIDIA RTX 5060 Ti, 16 GB. All reported model timings and accuracy evaluations use the homelab; FEM linear algebra runs on its CPU. Timing is not camera-to-display latency.

### 1. Numerical FEM, without neural weights

```sh
python fem/run_verification.py --element P1
python fem/run_benchmarks.py
python fem/ruler/verify.py
python figures/figure1.py
python figures/figure4.py
python figures/figure5.py
python figures/table3.py
```

Figures 4–5 can be rendered from the included publication inputs without GPU inference. Figure 4 additionally uses the P1 prior generated by the first command. Figure 2 is written to `fem/results/benchmarks/`; the other regenerated figures and Table III are under `runs/`. Figure 3 is the experimental photograph in `reference/figures/figure3.png`.

**P1 and Q4 are both implemented**, with explicit element gradients, matrices and sparse assembly. P1 uses linear triangles; Q4 uses bilinear quadrilaterals and 2×2 Gauss integration. `--element Q4` selects Q4 for the general verification solver; `python fem/ruler/solve.py --help` describes the interchangeable coil/ruler solver. All paper learning targets and plotted FEM fields use P1. Q4 is an optional solver, not another neural training target. Verification meshes are shipped, including their physical boundary/material tags.

### 2. Recover the exact published artifacts and recompute accuracy

```sh
python tools/download_assets.py dataset models geometry predictions
python tools/audit.py
python tools/evaluate.py
```

The downloader verifies SHA-256 hashes of each release part and extracted research file. It needs about 20 GB of free space while joining/extracting the split archives. `asset_manifest.json` records individual files and checksums. The default download is approximately 8.4 GB compressed, excluding the optional physical-training cache. `geometry` contains reviewed-mask coordinates and the fixed physical-baseline output used by the residual adapters. `predictions` contains the eight RGB methods' test predictions. The physical method is reconstructed from its verified geometry cache. Metric replay does not train or replace any checkpoint.

### 3. Run the checkpoints on the test images again

```sh
# Accept the upstream DINOv3 license/access conditions before downloading.
# Authenticate with your own Hugging Face account; never commit its token.
python tools/download_backbones.py
python tools/evaluate.py --infer
python tools/benchmark.py
```

The official backbones are **DINOv3 ViT-S/16** and **I-JEPA ViT-H/14**. Download revisions and weight SHA-256 checks are pinned. Alternatively, set `PHYSICS_ENCODERS` to a directory containing `dinov3/` and `ijepa/`, each with `config.json`, `preprocessor_config.json` and `model.safetensors`. Checkpoint inference restores the saved encoder deltas and potential decoder; frozen models restore only the learned decoder. Residual models use frozen pooled RGB features, train-only PCA-128, physical query features and their learned residual head. They require reviewed geometry; the six dense RGB methods do not use masks, YOLO or a FEM solver at inference.

`tools/evaluate.py --infer` evaluates all eight RGB checkpoints and compares the eight paper error columns against the archived results. `tools/benchmark.py` separately executes the physical ensemble afresh and includes it inside residual-method timing. Reference timing uses 12 warmups and 100 synchronized batch-one measurements at 448×448: FP32 for the physical ensemble and BF16 autocast for the RGB models. Disk access, preprocessing, transfers, detection, FEM solution and rendering are excluded. Parameters include frozen encoder parameters and, where required, the three physical-ensemble members. Timing naturally varies with machine load; `reference/inference_homelab.json` is the paper's measurement, not a promise of identical speed on another machine.

## Dataset and comparison

| Source | Meaning | Train | Validation | Test |
|---|---|---:|---:|---:|
| IP+LED | iPhone recordings with LED calibration setup | 206 | 18 | 34 |
| ST | Synthetic scenes | 191 | 29 | 26 |
| IP+RULE | iPhone recordings with metallic ruler | 358 | 28 | 26 |
| WB | Webcam recordings | 171 | 24 | 32 |
| Total | | 926 | 99 | 118 |

`experiments/field/config/manifest_docente.json` is the authoritative accepted-frame manifest. Splits are by video or synthetic scene family, not random adjacent frames. All nine methods share these images, P1 targets and LED amplitude mapping. The main test errors equally weight four reserved recorded videos (92 frames); 26 synthetic images are scored separately. The reserved recordings were inspected during development, so this is a diagnostic evaluation, not a new blind capture experiment. Internal identifiers such as `legacy_led`, `iphone`, `webcam` map to IP+LED, IP+RULE and WB respectively; they do not denote different experimental protocols.

The physical adapter and two frozen residual adapters receive reviewed geometry. The six direct RGB variants use a frozen encoder, the last quarter of encoder blocks, or full fine-tuning. That input distinction is part of the comparison. The FEM is the target definition, not independent physical ground truth. Near-zero IP+LED error of the physical baseline includes structural reuse of the no-ruler FEM prior.

## Calibration and figure interpretation

Five LED activation distances (5, 6, 6.5, 12, 17 cm) and assigned forward voltages (3.3, 3.1, 2.5, 2.1, 2.0 V) define a power-law scale. A monotone transfer maps the normalized P1 potential to LED-equivalent voltage. This is not a direct measurement of coil terminal voltage. Applying this transfer to ruler scenes is a modelling assumption; outside the supported amplitude interval it extrapolates. The ruler is grounded in the paper targets.

Field magnitude is the gradient of the calibrated predicted potential on the original 448-pixel grid, in equivalent V/pixel. Figure 5 uses a common train-derived color limit and fixed potential range; no per-image normalization or post-hoc smoothing. Its saved crop/mesh/PCA provenance is in `reference/figure_inputs/`. Prepared publication figures are reference compositions, with the separate rights described in `LICENSING.md`.

## Retraining or rebuilding targets

The release is frozen for reproducibility. Retraining is **optional**, not needed to reproduce the reported numbers. See [REPRODUCING.md](REPRODUCING.md) for an isolated training workspace and the original selection rules. No test-driven tuning is permitted by that protocol. The complete training histories, calibration, immutable checkpoint hashes and model-selection records are included. Historical acquisition paths in provenance are informational; released commands resolve their inputs within this repository.

See [validation/REPORT.md](validation/REPORT.md) for the checks performed on the packaged release and [LICENSING.md](LICENSING.md) for data, code and model rights. DINOv3 and I-JEPA retain their upstream conditions; I-JEPA is noncommercial.
